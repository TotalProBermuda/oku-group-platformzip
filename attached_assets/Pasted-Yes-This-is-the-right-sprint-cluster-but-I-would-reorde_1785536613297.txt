Red-Team Corrections
#180 should ship first.
This is the cleanest trust fix: if a referrer context exists, the system must never fall back to DIRECT. But be careful with one detail: PENDING_ATTRIBUTION should probably be a status or anchorStatus, not necessarily a source. Source answers “where did this come from?” Status answers “is this fully anchored?” Better model:
source: "QR" | "LINK" | "WHATSAPP" | "HOST_ENTRY" | "DIRECT"
anchorStatus: "ANCHORED" | "PENDING_ATTRIBUTION" | "FAILED_REVIEW"
That avoids semantic confusion later.
#181 should not wait for #182.
Capacity is a restaurant operations risk, not just a ledger risk. Add the space/hold model now. I agree with “warn, don’t hard-block” in v1, because host judgment matters. But the warning must be auditable:
capacity_warning_shown
capacity_overridden_by_host
capacity_hold_created
capacity_hold_released
Also add requestedSpaceId and assignedSpaceId. Referrer/customer can request Terrace; host assigns OKÜ/VIP/Catch based on reality.
#182 should be narrowed.
Do not ask Replit to fully backfill payout eligibility, admin UI, duplicate event audit, INVU minting, manual review, and payout gates all in one pass. That is how you get half-wired infrastructure. For this sprint, make #182 foundational:

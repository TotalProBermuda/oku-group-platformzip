P1 — Legacy-only dashboard can still crash in commission fallback.
In `/api/v1/referrer/dashboard`, the new earnerWhere logic appears to do:

if (legacyReferrer) {
  const earnerScope = await resolveEarnerScopeForReferrer(legacyReferrer.id);
  earnerWhere = earnerScope
    ? commissionWhereForEarner(earnerScope)
    : commissionWhereForActorOnly(actor!.id);
}

For a true legacy-only referrer, `actor` is null. If `resolveEarnerScopeForReferrer()` returns null, `actor!.id` crashes.

Fix:
For legacy-only fallback with no actor and no earnerScope, query by the legacy referrer id or return an empty safe commission where. Do not use `actor!.id` unless actor exists.

P1 — Candidate actors with inactive links may get a new code instead of reusing/reactivating the existing code.
In create mode, candidateActor includes only active links:
`links: { where: { isActive: true } }`

If a matching actor has an inactive ReferralLink/code, the resolver will create a new random code instead of reactivating/reusing the existing link. The plan said “existing ReferralLink/code tied to any candidate actor” should be considered.

Fix:
When reusing a candidate actor, load active and inactive links. If no active link exists but an inactive link exists, reactivate the most recent or safest existing link and mark `referralLinkReused: true`.
